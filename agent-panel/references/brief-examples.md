# Brief examples

Use these examples to make a brief concrete. Adapt the goal, evidence, deliverable and acceptance criteria to the user's request. They are illustrative prompts; the runner does not load them or assign a task category.

## Compare alternatives

Compare two queueing approaches for the supplied service constraints. Return a recommendation with alternatives, trade-offs, assumptions and unresolved experiments. Judge the recommendation against ordering, failure recovery, throughput and operating cost. A diagram is useful only if it explains the proposed flow.

## Investigate evidence

Determine what the supplied evidence establishes about the reported trend. Return a cited answer that distinguishes observations from inference, resolves conflicting sources where possible, and states uncertainty. Important claims must be attributable to a source. An inconclusive answer is valid when the evidence is insufficient.

## Review a change

Review the exact supplied diff against its intended behavior. Return material findings with locations, failure scenarios and supporting evidence. Validate disagreements and merge duplicate findings. An explicit empty findings list is complete when no material defect is supported. Do not apply fixes.

## Implement behavior

Implement the specified behavior in the selected repository revision. Return the assembled changes, a concise explanation, and results from the named checks. Cover the supplied edge cases and preserve unrelated behavior. For competing solutions, select one base and port useful improvements. For complementary work, resolve interfaces and integrate in dependency order.

## Diagnose a failure

Reproduce the stated symptom and establish its cause using the supplied logs, code and checks. Return the reproduction, causal evidence and remaining uncertainty. Keep source unchanged unless a correction is requested. A check may intentionally expect failure to verify a reproduction; specify that expected exit code explicitly.

## Produce finished writing

Write the requested artifact for the named audience, purpose, tone, format and length. Return finished copy. Preserve supplied facts and required points, and identify assumptions separately when needed. Review the copy against those constraints rather than imposing a standard report layout.

## An unfamiliar task

Allocate observation slots for a fictional moon. Return the allocation and the reasoning needed to verify it. Each requested observer must receive one slot, slots must not overlap, and every stated visibility constraint must hold.

No new runtime type is needed for this or another subject. Specify the deliverable and checks in the brief, then choose the access needed to do the work.
