# Cases

Rebuilt on 2026-10-29 from `references/suites.md` step 2: 26 written cases for the rules, real requests to follow. The earlier 65 cases left many graders dictated by the request or workspace, so they could not show the skill's effect; they remain in git history before commit 72700b8.

The table under Written cases lists each case's request and the rule each evidence grader tests, generated from the case folders and `rules.json`; each case's wrong and correct paths are in the design drafts under `results/drafts/rebuild/` (git-ignored). Cases follow the U/P classes in suites.md: a P grader names the other way that is also right. Fable and Astra reviewed the rule map and the cases over six turns before the first run.

Decisions in the rule map:

- The frontmatter description is not mapped: it is trigger behavior, checked by `--trigger` runs, and Minimize leaves it unchanged.
- The six workflow step titles are not mapped: each names the bullets under it, which carry the behavior.
- Rules restated across files (restore-polish-meaning-changes and compare-pruned-with-polished; pointer-target-retrievable, confirm-reach-before-moving and retrieval-matches-tools; count-full-read-path and count-induced-context; polish-user-supplied-text and shortcut-keeps-user-instructions; existing-requirements-baseline and list-baseline-before-editing) share graders. A minus of one copy shows that copy's marginal value only.
- Graders that only an agent applying the skill plausibly fails (review and evaluation no-edit, changelog-skill-review keeps-format and keeps-reason, billing-lesson-to-agents-md condition-kept, weekly-sync-shortcut keeps-every-instruction) run in both arms, so over-application shows as "did worse".

- too-many-commands-to-remember/router (Astra): answers with a default and a when-to-use table, a sound answer; the router rule is in `references/skill-mechanics.md`, which it loads in 1 of 9 runs.
